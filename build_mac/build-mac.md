# Building the API libraries on macOS

These steps build the macOS equivalents of the two libraries in `deploy/api/`:

| Windows | macOS | Source | Used by |
|---|---|---|---|
| `solarpilot.dll` | `solarpilot.dylib` | [mjwagner2/ssc](https://github.com/mjwagner2/ssc), branch `solarpilot-develop` | `copylot.py` |
| `coretrace_api.dll` | `coretrace_api.dylib` | [NREL/SolTrace](https://github.com/NREL/SolTrace) | `pysoltrace.py` |

wxWidgets, LK and WEX are not needed; those are only for the GUI.

Last tested 2026-10-20 on an Intel Mac (x86_64), macOS 26.6, AppleClang 21, CMake 4.4, with
SSC `e9469f3` and SolTrace `6169a90`.

## 1. Prerequisites

- Xcode Command Line Tools (`xcode-select --install`)
- CMake 3.19 or newer (`brew install cmake`)

## 2. Clone the source repositories

Clone them next to this repository (any location works, as long as the environment variables below point to it):

```sh
cd ~/Documents/GitHub
git clone -b solarpilot-develop https://github.com/mjwagner2/ssc
git clone https://github.com/NREL/SolTrace
```

### Pin SolTrace to a compatible commit

The current SolTrace `develop` branch (2026 and later) is a major refactor: `coretrace_api` is built as a
static library, and `coretrace` won't compile without the OptiX headers. Use the last commit before that refactor:

```sh
git -C SolTrace checkout 6169a902e33f   # 2025-09-16, "Fix ZAperture calculation for parabolic surfaces"
```

## 3. Patch SSC

These two fixes are required for clang. Neither changes Windows behavior.

**`ssc/solarpilot/interop.cpp`, line 55**: remove the trailing semicolon. clang rejects `#if HELIO_INTERCEPT`
when the macro expands to `false;`:

```diff
-#define HELIO_INTERCEPT false;
+#define HELIO_INTERCEPT false
```

**`ssc/solarpilot/CMakeLists.txt`**: the post-build copy hardcodes `.so` on all non-Windows platforms. On macOS
the copy fails, which makes the build fail and delete the finished `.dylib`:

```diff
-		set(COPILOT_DLL $<TARGET_FILE_DIR:solarpilot>/$<TARGET_FILE_BASE_NAME:solarpilot>.so)
+		set(COPILOT_DLL $<TARGET_FILE_DIR:solarpilot>/$<TARGET_FILE_BASE_NAME:solarpilot>${CMAKE_SHARED_LIBRARY_SUFFIX})
```

## 4. Generate the nlopt `config.h`

nlopt needs a `config.h` generated by its `configure` script (Windows uses the checked-in `config-windows.h` instead).
Run it out of tree so it doesn't litter the source folder, then copy the result in:

```sh
mkdir -p /tmp/nlopt_cfg && cd /tmp/nlopt_cfg
~/Documents/GitHub/ssc/nlopt/configure
cp config.h ~/Documents/GitHub/ssc/nlopt/config.h
```

## 5. Set environment variables

```sh
export SSCDIR=~/Documents/GitHub/ssc
export CORETRACEDIR=~/Documents/GitHub/SolTrace/coretrace
```

## 6. Configure and build

`build_mac/CMakeLists.txt` is a small parent project that pulls in SolTrace's `coretrace` targets and SSC with
`BUILD_COPILOT_API=ON`, because SSC's `solarpilot` shared library links against the `coretrace` target.

```sh
cd ~/Documents/GitHub/Solarpilot/build_mac
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
  -DCMAKE_CXX_FLAGS="-D__64BIT__ -DSP_STANDALONE -DSP_USE_SOLTRACE -DSP_USE_THREADS" \
  -DCMAKE_C_FLAGS="-include $(xcrun --show-sdk-path)/usr/include/sys/time.h"
cmake --build build --target solarpilot coretrace_api -j8
```

What the flags are for:

- `CMAKE_POLICY_VERSION_MINIMUM=3.5`: SSC declares `cmake_minimum_required(VERSION 2.8)`, which CMake 4 refuses.
- `CMAKE_CXX_FLAGS`: SSC's `solarpilot/CMakeLists.txt` sets these definitions for Windows and Linux but not for
  Apple. Without `SP_USE_SOLTRACE` the library builds without SolTrace support.
- `CMAKE_C_FLAGS`: `ssc/nlopt/sys/time.h` is a Windows-only shim that shadows the system `<sys/time.h>` (because
  nlopt compiles with `-I.`), leaving `gettimeofday` undeclared. Force-including the real SDK header fixes it.

## 7. Copy the libraries into `deploy/api`

```sh
cp build/ssc/solarpilot/solarpilot.dylib ../deploy/api/
cp build/coretrace/coretrace_api.dylib   ../deploy/api/
```

Both libraries depend only on system libraries (`otool -L` shows just `libc++` and `libSystem`).

## 8. Check the build

The Python wrappers load the libraries from the current working directory, so run from `deploy/api`:

```sh
cd ../deploy/api
python3 -c "from copylot import CoPylot; cp = CoPylot(); r = cp.data_create(); print(cp.version(r))"
python3 min_example.py
```

To check `coretrace_api.dylib` together with SolarPILOT, run `test_solarpilot_soltrace.py`. It expects the
weather file in the current folder, so first change its `weather_file` path to
`../climate_files/USA CA Daggett (TMY2).csv`.

## Notes

- **Architecture:** these steps were tested on Intel. SSC's `solarpilot/CMakeLists.txt` hardcodes
  `-arch x86_64` on Apple, so an Apple Silicon build would need that changed (or
  `-DCMAKE_OSX_ARCHITECTURES="x86_64;arm64"` for a universal binary). This hasn't been tested.
- **`pysoltrace.py`** loads `coretrace_api.dylib` on macOS. The module-level `loaddll()` helper (used only by the
  file's own `__main__` timing test) is still hardcoded to `coretrace_api.dll`.
